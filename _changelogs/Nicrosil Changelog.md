The changelog of [[Nicrosil]], newest first. It lives here in `_changelogs/`, outside the guide, so an agent reading the guide doesn't also read all of this. Read it only to add a line for a new version or to look up when something changed. Past lines are never rewritten; a correction goes in a new line. How something looks (corners, fonts, colors, animations) belongs in these lines, not in the guide's body.

- **3.6.1:** Middle-click in the Tinmind's course tree. Every row (a course, a note, a heading on a course page, All Class Notes) opens in a new tab on a middle-click, the same as `Ctrl+click`; before, only note rows did, and the middle button could start the browser's scroll cursor. The tree's rows now stop that cursor on a middle-press and share one handler in `tinRow`; **New course**, **New semester** and folders ignore the middle button, so they don't make a dialog or open and close by accident. The note rows' own middle-click handler was removed, since the shared one replaces it.
- **3.6.0:** Two changes to the notes in `The Tinmind/`. (1) **A pill that goes back to the course page.** A note inside a course (its folder has a course page of the same name, such as `Fall 26/Chinese I/` and `Fall 26/Chinese I.md`, at any depth) shows a pill above its title: an arrow and the course's name, in a 0.5px outline of `#8f86b8` with a lilac arrow, filling with a dark lilac (`#2e2a45`) and a `#b8a3f2` outline on hover. Click or Enter opens the course page; Ctrl+click opens a new tab. It is drawn on screen, not part of the file, and is not shown on course pages, the Tinmind Dashboard, All Class Notes or hover previews. **New note** no longer writes the `← [[course page]]` line, and a one-time step (`tinCourseLinksRemoved` in `data.json`) removes that line, and the blank line after it, from existing notes that have `type: course-note` (only a line at the start of a line pointing into `The Tinmind/`; the count is shown). (2) **No properties on any note in the Tinmind.** The Properties block and the one-line strip are hidden on every note there (course pages and the notes in a course), as on the Tinmind Dashboard. The properties are still in the files, and Nicrosil still reads them.
- **3.5.0:** Two changes to the Tinmind's notes. (1) **New note's name is filled in.** The box opens with `<course> mm-dd-yy` for today, for example `Freedom's Foundations 1 11-22-26`, with the cursor at the end so Enter takes it or typing adds to it. The date uses dashes because a file name can't contain `/`. A second note on the same day becomes `... 11-22-26 2`. It applies to every New note (the course page's button, the **+** on a course, and **New note here** on a folder). (2) **Course pages are named for the course.** `Fall 26/SAIL Notes.md` is now `Fall 26/SAIL.md` (the folder of its notes, `Fall 26/SAIL/`, is unchanged); **New course** makes it that way. A one-time step renames the existing ones with Obsidian's own rename (links follow, and a course's open/closed state in the tree is kept). It only renames a note directly in a semester folder with `type: class-notes`, and skips one if the new name is already taken or another note anywhere in the vault already has that name, because links by name would turn ambiguous; skipped ones are named in a notice. It runs at startup and again once Obsidian has indexed the properties (`tinHubsRenamed` in `data.json` is set when every one was seen).

Changed `syncHomeButtons` in `main.js` and the 3.4.0 block in `styles.css`.

Changed `syncHomeButtons` in `main.js` and a block after the `.cm-underscore-btn.is-active` rule in `styles.css`.

Before, a note opened in the same tab as the Tinmind Dashboard kept that tab's Reading view, and "Every page" put them there too. Course tree rows, course page headings and links all go through the same step. As with the other pages, switching a note to Reading view yourself sticks until that tab opens a different page.
- **3.3.0:** Two changes to the Tinmind's notes. (1) **Titles in TGS.** Every note in `The Tinmind/` (course pages, the notes inside a course, notes made later, the All Class Notes page) shows its title in the Tinmind Gradient Style: Almendra SC, weight 600, the grey-lilac gradient run across the title's own width (`--cm-title-w`), and the Tinmind glow, whatever its `status`. The pane gets the class `cm-tinnote-leaf`. The Tinmind Dashboard keeps its hero. (2) **No dashboard link in course notes.** Course pages had `← [[The Tinmind/Notes Dashboard]]` under their properties (later pointing at Tinmind Dashboard). On the first start after the update, a one-time step (`tinBacklinksRemoved` in `data.json`) removes any line in a note under `The Tinmind/` that is only that link (`← [[... Notes Dashboard]]` or `← [[... Tinmind Dashboard]]`) and shows how many notes it changed; nothing else in a note is touched. The Tinmind Dashboard, the All Class Notes page and the files outside `The Tinmind/` are skipped. **New course** makes a course page with properties only. The `← [[course page]]` line in notes made inside a course stays.
- **3.2.1:** Obsidian always starts in the Coppermind's mode. - **3.2.0:** Four changes to the Tinmind. (1) **All Class Notes** is gone from the Tinmind Dashboard's cards; it is only a row in the course tree (the page and its table are unchanged). (2) **New semester**, a row under **New course** in the course tree (calendar-plus icon): it asks for a season and a year, suggests the next one after the newest (Fall 26 gives Spring 27; Spring 27 gives Fall 27), tidies the name to `Season YY` (so `fall 2027` becomes `Fall 27`; any other name is refused, because the semesters are sorted by date), makes the folder `The Tinmind/<Semester>/` and switches the tree and the Dashboard to it. A semester made this way stays in the Semester boxes while its folder exists, even with no course in it; the list is kept in `data.json` (`tinSemesters`). **New course** then makes the first course page. (3) The **Notes in this course** panel no longer appears on the Tinmind Dashboard: the panel is also hidden on that page and the All Class Notes page, and cleared when a pane switches to it, which left it stranded after a course page. (4) The Tinmind page is renamed **Tinmind Dashboard** (was Notes Dashboard). On startup, and when the Tinmind button is used, a one-time step renames `The Tinmind/Notes Dashboard.md` with Obsidian's own rename, so links to it (the back-links on course pages) follow; nothing else in the vault is touched. The Dashboard page's `type: notes-dashboard` property is unchanged.

Delete asks first and moves to the trash (a folder says how many files are in it); rename uses Obsidian's own, so links follow. Names are cleaned of `\ / : * ? " < > | # ^ [ ]`, and a name already taken gets " 2". A new note is `type: course-note`, `course`, `semester`, then `← [[course page]]`, and opens in the editing view. **New course** makes `<Semester>/<Course> Notes.md` with `type: class-notes`, `course`, `semester`, `current` (as the others in that semester), `order` (next number) and a link back to the Tinmind page. Which courses and folders are open is saved in `data.json` (`tinOpen`). **On a course page** (any note with `type: class-notes`, not in a hover preview) a panel is drawn right under the properties: the title "Notes in this course" in the Tinmind gradient, **New note** and **New folder** buttons, and the same list. It is drawn on screen, not written to the page, so the file is untouched and the properties strip stays. Switching into the mode now also opens the left sidebar on the file list. The tree and panels redraw when anything in `The Tinmind/` is made, renamed, deleted or its headings change, and when the open note changes, only if what they show changed. The tree reads folder names and Obsidian's list of headings and properties, never the notes' text. Not included: renaming or deleting a course, starting a semester, reordering notes.
